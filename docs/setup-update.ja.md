# 再セットアップ時の依存更新とディスク容量

## 依存パッケージの更新

BNLはホストのbackend/frontendをコンテナへマウントします。このため、イメージだけを再ビルドしても、ホストに残った古いnode_modulesは更新されません。

起動時にinstall-dependencies.shが、package.json・package-lock.json・Nodeのバージョン/プラットフォーム/アーキテクチャ/ABI・npmのバージョンを照合します。記録がない場合や変更がある場合は、APIと画面を起動する前にnpm ciで依存を更新します。変更がなければ再インストールしません。

- 旧版からの初回更新時は、既存のnode_modulesがあっても再インストールします。ネット接続と空き容量が必要です。
- インストール失敗時は起動を中止します。成功記録を残さないため、次回起動時に再試行します。
- package-lock.jsonがない場合も起動を中止します。ロックファイルを削除して対処しないでください。
- 更新対象はアプリの依存パッケージです。ノードデータ・鍵・バックアップは削除しません。
- Setupの起動確認は最大300回行います（各回2秒待機に確認処理の時間を加えた上限）。遅い回線などで上限に達した場合は、コンテナログを確認してください。

## ビルド対象からの除外

shared全体を.dockerignoreで除外し、Dockerfileでは空の/app/sharedだけを作成します。設定・鍵・保存済みバックアップは実行時のバインドマウントから使用します。元のsharedを削除する変更ではありません。

この修正は新しく作るイメージへの混入を防ぎます。過去のイメージやキャッシュ、保存済みZIPを自動削除したり、WSLの仮想ディスクを圧縮したりはしません。既存イメージには秘密情報が含まれている可能性があるため、配布しないでください。

修正の適用にはイメージの再ビルドが必要です。Windows側とWSL側の空きを確認した後、修正版のSetupで更新してください。古いイメージの整理は正常起動を確認してから行います。

## 回帰テスト

リポジトリ直下で実行します。WindowsではGit Bash、Linuxではbashを使用します。必要ならBNL_TEST_BASHでbashの場所を指定できます。

```sh
node --test setup-runtime.test.cjs
```

依存更新の判定・失敗後の再試行・ビルド除外をテストします。npm/Node検出はテスト用コマンドに置き換えるため、実際のDockerビルドやネットワーク経由のnpmインストールは別途確認が必要です。
